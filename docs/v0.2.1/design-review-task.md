### Step 4: 梳理详细执行流程

#### 4.1 心跳完整流程
```
1. 心跳触发（定时器）
2. 读取配置（consciousness.*）
3. 读取当前情绪状态（EmotionState）
4. 计算时间间隔（minutes_since_update）
5. 调用 evolve_emotion() 演化情绪
6. 获取当前时间窗口权重（get_time_fitness()）
7. 获取沉默时长（silence_minutes）
8. 读取延迟队列
9. LLM 评估：
   a. 输入：近期 session + Hindsight + 天气 + 当前情绪
   b. 输出：新的 VA 值 + 念头 + 念头类型
10. 合并情绪（演化值 + LLM 评估值）
11. 决策计算（make_decision_v2）
12. 处理决策结果：
    a. auto_send → 生成消息 → 发送 → 记录日志 → 保存情绪
    b. delay_send → 入延迟队列 → 记录日志
    c. memory → 存入 Hindsight → 记录日志
    d. skip → 仅记录日志
13. 重评估延迟队列
14. 更新状态到数据库
15. 记录心跳日志
```

#### 4.2 消息发送流程
```
1. 接收发送请求（content, emotion_state, thought_type）
2. 生成消息内容（LLM）
3. 调用 send-and-inject API
4. 更新最后发送时间
5. 触发冷却期
6. 更新发送计数
7. 保存情绪状态
8. 存入 Hindsight（如果符合条件）
9. 记录发送日志
```

#### 4.3 延迟队列处理流程
```
1. 读取延迟队列
2. 遍历每个延迟念头
3. 计算新的 score：
   a. 获取当前情绪状态
   b. 获取当前时间权重
   c. 获取沉默时长
   d. 应用决策公式
4. 判断处理方式：
   a. score > send_threshold → 升级为发送
   b. score < 0.1 → 降级为丢弃
   c. 否则 → 保持延迟，更新 score
5. 更新队列状态
```
