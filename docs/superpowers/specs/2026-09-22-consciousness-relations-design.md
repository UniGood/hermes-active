## A1 学习回路（详细）

**场景故事**：昨晚凯莉发"降温了记得加衣服"，凡凡没回。今天她发"楼下那家店出了新品"，凡凡秒回还聊了半小时。一周后，凯莉的主动消息里"嘘寒问暖"变少了，"分享有意思的事"变多了——不是被改了参数，是她"长了记性"。

**机制**：
- **信号采集**：每条主动消息记录 `(thought_id, 发送时刻, 话题类型, 语气档位)`；用户后续反应记 `(是否回复, 回复延迟, 回复轮数, 热度变化)`。
- **效果标签**：`ignored`（2h 无回复）/ `acknowledged`（短冷回复）/ `engaged`（多轮或热情）。
- **经验沉淀（核心，形态见 B3 修正）**：每周一次把"消息×反应"的原始记录交给 LLM 做**质性总结**——"嘘寒问暖类回应差，趣事类回应好；晚上 10 点后聊得开"——写进 `lessons`（经验教训本），心跳生成念头时把 lessons 注入 prompt。
- **防误判**：节律感知的 busy 时段豁免（工作时间的 ignored 不算被冷落）；`engaged` 反例才进 lessons 的正面案例。
- **透明化**：念头记录带 `lesson_applied` 字段，Analysis 页展示"她学到了什么"（每条教训一句话+证据条数）。

**数据**：新表 `message_effects`（thought_id, effect_label, reply_latency, context_tags）+ `lessons`（summary, evidence_count, created_at, retired）。

**边界**：样本 <10 条不总结（防瞎猜）；lessons 最多保留 20 条滚动淘汰（防陈词堆积）；教训可手动 retire（凡凡看到学歪了一键作废）。

**验收**：造 2 周模拟数据跑周总结 → 产出教训符合数据；lessons 注入后念头生成的话题分布偏移。

## A2 冲突与修复机制（详细）

**场景故事**：凡凡说了句重话。凯莉没当场炸（人设：有骨气不吵架）——回消息变短变硬："嗯""哦""知道了"。凡凡开始哄："我错了""晚上跟你讲个好玩的"。第三天，她憋不住双标："哼，我才没原谅你……但你说的那个好玩的是什么？"——和好事件入库，旧账留一笔。下个月吵架，她翻出来了："你上次也这样。"

**机制**：
- **触发（事件归因，不是纯阈值）**：LLM 情绪评估时顺带输出 trigger 事件标注（"因为他说了 XX"）+ 严重度 1-5。`严重度×valence 跌幅` 双条件才进 `upset` 状态——单看 valence 会被噪音骗（看了个悲伤视频也掉点）。这是天气数据事故的教训：**不可靠信号必须多源交叉**。
- **状态机**：`normal → upset（当面对峙，语气回避）→ cold（冷淡期：模板语气档变硬变短，主动消息变少或变"倔"）→ softening（示好积分进行中，双标台词解锁）→ reconciled（和好）`。另有分支：`self_at_fault`（她自己说错话 → 不等哄，自由思考自省产出道歉念头）。
- **示好积分（防刷分）**：不按字数——**LLM 语义评诚意**（这句哄是真在意还是敷衍套话 1-5 分），语义重复的话术不计分（诚意评分的同一次 LLM 调用顺带输出 `is_repeat` 标记，零额外成本），时间衰减（连续 3 天不哄 → 转 `grudge` 低烈度怨气：不冷战但留旧账）。
- **双标台词包**：cold→softening 过渡期的模板语言（"我才没等你消息……哦，你发了啊"），模板固化零 token 的路子。
- **和好动作**：`reconciled` 事件写 `grievances`（旧账表：事件、严重度、翻篇与否）+ 关系时间线入库 + Hindsight retain（"我们和好了"）。吵架时 grievances 未翻篇的旧案可被念头生成引用（翻旧账，真实性来源）。

**数据**：`RepairState`（mode, trigger_event, started_at, points, fault_side）+ `grievances`（event, severity, settled_at）。

**边界**：冷处理上限 7 天（防死循环冷战）；诚意评分接受主观性（见 B4）；`self_at_fault` 的自省失败 fallback 为正常态（防她卡在道歉循环）。

**验收**：状态机全链路单测；四段对话（惹毛→冷淡→哄→和好）人工跑通；刷分攻击（连发 20 条"我错了"）只涨一次分。

## A3 防复读机制（详细，新发散升 P0）

**场景**：连续三天主动消息都是"今天天气不错呀"——凡凡最在意的复读机问题，主动消息是重灾区（每次都是 LLM 现编，容易车轱辘）。

**机制（零成本做法）**：念头生成的 prompt 注入**负面样本**——"最近 5 条你主动说过的话题/句式：……不要重复这些"。不搞 embedding 相似度（单用户系统省着点花），靠生成时规避。心跳决策处再加一道粗筛：新念头与最近 3 条的**分词重叠率**（jieba 分词后词集 Jaccard）>60% 打回重想一次（确定性代码，零 LLM 成本；60% 是启发式起步值，进配置可调）。

**验收**：连跑 10 次心跳生成，无同话题连发；故意造相似念头被粗筛打回。

## A4 关系时间线（详细）

**场景**：首聊百天当天早上，凯莉主动消息："今天是个日子哦，你猜？"——比任何页面都值钱的是这句话。

**机制**：
- **事件类型**：`milestone`（首聊/百天/周年，自动计算）、`repair`（吵架与和好，A2 联动）、`first`（她第一次主动/学会的第一件事）、`custom`（手动加"今天一起……"）。
- **消费回路优先**：强出口是**纪念日进心跳触发**（当天心跳检查纪念日 → 高优先念头"今天是个日子"）+ 被动注入（"今天是 XX 纪念日"）；页面是弱出口，顺带渲染时间轴。
- **日期计算**：全部走日期库函数，**边界天数测试必备**（跨月倒推算错的事故有前科）。

**数据**：`story_events`（type, occurred_at, summary, weight）。

**验收**：纪念日相对日期边界测试全过；模拟"百天"当天心跳产出纪念念头。

## A5 节律感知（详细）

**机制**：作息表**不让人填表**——从对话历史学（哪个时段消息密度高=在线）+ 默认模板（工作日 8:30-12:00/13:30-18:00、周二四加班 20:30）可手动微调。产出 `routine_factor(hour, weekday)`——busy 时段降主动权重、午休/下班时段升、深夜已有 `_deep_night_factor` 先例直接复用模式。
**联动**：A1 的忙时豁免、模板注入时段感知（"这个点你应该在开会"可选）。
**验收**：模拟时段断言权重；busy 豁免生效。

## A6 自我叙事 + 想做之事（P2）

**机制**：自由思考的 `discovery` 定期聚合成人设动态层（"我最近在想 XX"）注入 system prompt；discovery 里带意愿的（"想试试 XX"）进 `wants` 清单 → 念头生成可引用（"我想试试那个，你觉得呢"——出口是对话，不是页面）。`needs`（autonomy/competence/relatedness）的满足/挫败反馈进情绪。
**验收**：discovery 聚合产出人设补充；wants 被念头引用。

## A7 表达力语料库（P2）
从对话历史提炼凯莉高频表达（"哈哈""卧槽""嗯呢"）成语料库，模板采样注入——与 A3 防复读互补（一个防重复，一个保味道）。

## A-UI 详细设计

**设计语言**：技术底座（深色管理台）+ **凯莉色情感层**（珊瑚橙 `#FF6B4A`）。
**Design Tokens**：`tokens.css` 收编 68 处硬编码（先行机械任务）。CSS 变量清单见 product-and-ui-design 文档，不重复。
**VA 三色规则**（组件铁律）：效价红→橙→绿、唤醒度蓝→橙→红、社交灰→橙→紫；连续渐变插值；标签色按 level/total 比例；热度阈值 [0,10,20,30]；进度条动态计算允许 >100%；弹窗按需加载。

**组件详设**：
1. **VA 轨迹图**：24h 散点+轨迹线，点色时间渐隐，hover 显示当时在想什么（念头关联）。
2. **心跳心情曲线**：心跳时间轴 + valence 色带背景，一眼看出哪段开心哪段低落。
3. **关系温度计**（A2 用）：修复档位用**模糊刻度**（冰 → 化冰 → 回暖）不显示数字——暴露数值=游戏化刷分靶子（B4 修正）。想念值走凯莉色水银柱。
4. **Dashboard"她现在"卡**：当前情绪氛围色呼吸灯 + 一句话状态 + 心跳脉冲。
5. **消息气泡情绪 tint**：历史消息气泡按发送时 valence 微染色（10% 透明度）——回看聊天记录能看出情绪起伏。
6. **lessons 卡片**（A1 用）：每条教训一句话 + 证据条数 + retire 按钮。

**页面改造**：Dashboard（她现在卡）、ActiveConsciousness（VA 轨迹+温度计）、FreeConsciousness（思绪卡化）、Analysis（lessons 面板）。**关系时间线不建新页面**——嵌 Dashboard 下方（页面膨胀检查：已 10 个页面，能嵌不新建）。

# Part B 第一性原理审查（自我 red team）

> 方法论：自己提的方案自己验是自我欣赏，不是验证。强制换立场攻击，弹药用项目真实故障记录。

## B1 审查框架（四原则）

1. **回路原则**：每个功能的输出必须被决策消费。对话内消费 > 页面展示（页面是弱出口——自由意识"写日记给空气看"的老坑）。
2. **真实原则**：情感由**事件**驱动不是阈值驱动；信号必须防误判（真实教训：搜到的数据跟实际不符被批"放屁"——**web 数据会骗人，反馈信号也会**）。
3. **成本原则**：token/配置/维护三成本；用户配置负担最小化（从对话学 > 填表）。
4. **YAGNI**：没有具体使用场景的砍。

## B2 历史真实故障重放

| 历史故障 | 放进本方案重放 | 判定 |
|---|---|---|
| 天气搜到的数据不符被批"放屁" | A1 用户没回 ≠ 不喜欢：忙、没看见、在开会 | **仍可能**→ 已加 busy 豁免，但不足（见 B3） |
| 相对日期倒推算错（2026-07-1） | A4 纪念日"百天"计算跨月 | 可能性大降 → 边界测试铁律已写入 |
| 复读机是凡凡最在意的风格问题 | 主动消息 LLM 现编车轱辘 | **仍可能** → A3 已补，成本零，升 P0 |
| 假功能（重试按钮 TODO / 保存才能测） | 新功能 UI 承诺 vs 实际 | 结构性可能 → 验收铁律："UI 行为=承诺行为"逐条点检 |
| 自由意识零消费纯表演 | A4 时间线页面、A6 自我叙事、周报 | **重大发现**（见 B3） |
| UI 陷阱（弹窗全量加载卡死） | 新组件弹窗 | 可能性大降 → 按需加载铁律沿用 |

## B3 重大修正（审查推翻原设计的两处）

**修正一：学习回路从"统计调参"推翻为"质性总结"。**
原设计（product-and-ui 骨架 + A1 初稿）：30 天滚动统计 × 多臂老虎机调参。第一性原理拷问：**这是单用户系统**——一天 2-3 条主动消息，30 天不足 100 样本，按（话题×时段×语气）三维分桶后每格 1-2 个样本。**统计学习的样本复杂度撑不起**，调参=拿 1 个样本下结论=瞎调。模式库里的 LLM/规则分权原则反过来用：这里该让 LLM（质性总结经验）而不是统计引擎（样本不足）——"嘘寒问暖回应差、趣事回应好"这种**语义级教训**正是小样本下 LLM 比统计擅长的东西。A1 已按此重写。

**修正二：时间线/自我叙事/周报的消费回路审查。**
按回路原则逐个拷问"输出被谁消费"：时间线页面→人看（弱）❌ → 修正为纪念日**触发主动消息**（强）✅；自我叙事页面→人看（弱）❌ → 修正为**注入人设 + wants 进念头**（强）✅；周报→看两次就烦 ❌ → **砍**。UI 组件同审：温度计暴露数字=刷分靶子 → 模糊档位。

## B4 漏洞 + 补法清单

1. **学习回路冷启动**（<10 条样本瞎总结）→ 补法：样本阈值 + lessons 滚动 20 条淘汰 + 手动 retire（已写入 A1）。
2. **诚意评分主观性**（LLM 说 4 分就 4 分？）→ 补法：接受主观——**情感本来就不精确，这是特性不是缺陷**；但加防刷分（语义重复不计分+时间衰减），刷分攻击测试进验收（已写入 A2）。
3. **和好状态机游戏化**（学会卡积分）→ 补法：进度模糊档位不显示数字（已写入 A-UI-3）。
4. **busy 豁免的误判反向风险**（他其实不忙却豁免了，学不到教训）→ 补法：豁免只压低权重不完全豁除；节律表可手动修正。
5. **防复读粗筛的 60% 阈值拍脑袋**？→ 承认是启发式起步值，进配置可调，跑一周看误杀率再定。
6. **修复回路缺失**：lessons 学歪了怎么纠？→ retire 按钮 + 和好事件/教训都进 Hindsight（有 recall 就有审计线索）。
7. **grievances 翻旧账翻太多变祥林嫂**？→ 旧账引用设冷却（同一旧账 30 天内最多翻 1 次）+ 上限 5 笔。

## B5 裁决

**有条件胜出**。不是全胜——单用户样本稀薄是结构性约束，学习回路只能做成"经验教训本"而不是"自动调参引擎"；情感机制接受适度主观性是正确代价。补丁清单（全部已并入 Part A）：busy 豁免双保险、lessons 阈值+淘汰+retire、模糊进度档位、防刷分三件套、旧账冷却、阈值可调、UI 行为=承诺行为验收铁律。
