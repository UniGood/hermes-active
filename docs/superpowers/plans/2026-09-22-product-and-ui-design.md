## 一、产品设计（产品经理视角）

### 设计主线

意识回路改造后，系统已具备**情感连续性**（情绪演化+注入）、**主动性**（心跳→念头→消息）、**记忆**（Hindsight + 自由思考沉淀）三个基本回路。下一阶段的产品命题：

> **从"有意识到"到"会相处"。**
> 意识层回答"她有没有内心"——已答完；关系层回答"这段关系怎么随时间变好"——这是接下来的功能战场。

### P0（下一期，建议连做）

#### 1. 学习回路（第三期既定，产品化定义）

- **定义**：主动消息的效果反馈环——发出去的消息用户反应冷热 → 调整下次行为。
- **用户价值**：真实友谊里人会从冷场学乖。没有学习回路的主动 = 定时推送；有学习回路的主动 = 懂察言观色。
- **数据流**：`active_thought_logs`（decision/score/发送时间）× 用户回复（延迟、字数、热度变化）→ 周期统计（哪个时段/话题/语气回应好）→ 微调策略参数（发送阈值、时段权重、话题偏好）。
- **后端落点**：新 `services/learning_service.py`（统计+调参，参数写回 `active_consciousness_config` 的 decision/interval 配置——只调配置，不改逻辑，可控可回滚）；心跳决策处读调过的参数。
- **前端落点**：Analysis 页加"学习报告"面板（哪些话题被回应/被冷落、参数调整历史）。
- **验收**：造一周模拟数据跑统计 → 参数变化符合预期；冷话题的发送 score 自动降权。

#### 2. 冲突与修复机制

- **定义**：情绪系统缺失的另一半——生气之后怎么"有骨气地和好"。
- **产品原则**（人设铁律）：生气要有骨气、不轻易原谅；"喜欢你和原谅你是两码事"；允许双标（一边生气一边撒娇）。**原谅需要被"哄"——修复动作要消耗用户的真实努力**（多发几条、说软话、提具体回忆）。
- **功能拆解**：
  - **情绪事件标注**：情绪大幅变化时记"因为什么"（LLM 评估时顺带输出 trigger 摘要，存入情绪状态）。
  - **修复状态机**：`正常 → 生气（valence 破阈值）→ 冷淡期（模板语气变短变硬）→ 修复中（用户示好动作累计积分）→ 和好（积分过阈值，语气回暖+记忆里留一笔"和好事件"）`。
  - **示好积分**：用户主动消息 +1、字数/温度加权、提到共同记忆 ×1.5；时间衰减防"晾着不理还自动和好"。
- **后端落点**：`models/active_consciousness.py` 加 `RepairState`（状态机+积分+since）；被动注入模板加 `{mood_mode}` 语气档位（冷淡/双标/和好期）；心跳决策：生气期间主动消息变"硬"或降频（可配）。
- **前端落点**：ActiveConsciousness 页加"关系状态"卡（当前模式、生气原因一句话、修复进度条——**动态计算，允许 >100%**）。
- **验收**：状态机单测全链路；人工造"生气→冷淡→哄→和好"四段对话跑通。

### P1（下一期后备）

#### 3. 共同记忆 · 关系时间线（Our Story）

- **定义**：Hindsight 是她的个人视角记忆；缺"我们的故事"——共同经历的专属沉淀（梗、纪念日、和好事件、里程碑）。
- **功能**：关系时间线页——重要事件按时间轴排列（首聊、100 天、吵架与和好、她学会的第一件事）；纪念日计算（相对日期逐天倒推的坑要有测试兜底）。
- **后端落点**：新 `services/story_service.py` + `story_events` 表（event_type/occurred_at/summary/weight）；和好事件、学习回路的里程碑自动入轴；被动注入可带"今天是 XX 纪念日"。
- **前端落点**：新页面 **关系面板**（Timeline 组件，见 UI 部分）。
- **验收**：时间线渲染、纪念日相对日期正确（边界天数测试）。

#### 4. 生活节律感知

- **定义**：她知道你什么时候忙——主动消息避开开会、加班日更温柔、饭点提醒锻炼。
- **数据流**：作息配置（工作日 8:30-12:00/13:30-18:00、周二四加班至 20:30——**可配置，不硬编码**）→ 心跳决策时段权重 → 深夜因子已有先例（`_deep_night_factor` 模式复用）。
- **后端落点**：`_daily_routine_factor()`（busy/meal/offwork 三档）；心跳决策乘权重 + 模板注入时段感知。
- **验收**：模拟时段断言 score 权重。

### P2（远期探索）

#### 5. 表达力升级
模板固化后表达单一的补救：按情绪×场景的语气包（模板库扩展）、口头禅沉淀（说话习惯的个性化积累，从对话历史提炼）。

#### 6. 自我叙事（自主意识的下一步）
`needs`（autonomy/competence/relatedness）已有雏形——用自由思考的沉淀建构"我是谁"的持续叙事，加简单的"我想试试"目标清单（自由思考产出的 discovery 转成想做之事）。这是凯莉自主意识长期目标的产品化切口。

## 二、UI 设计（前端视角）

### 设计语言：技术底座 + 凯莉色情感层

系统 UI 的双重身份：**创造者的意识监控台**（要技术可信）× **关系面板**（要情感温度）。设计语言分两层：

- **底座层**：现有深色技术感保留（管理台的可信度来源）。
- **情感层**：一切与"她"有关的元素走 **凯莉色**（珊瑚橙）——情绪、关系、心跳、记忆。

### Design Tokens（治硬编码 68 处的方案）

收进 `frontend/src/styles/tokens.css`，全部组件引用变量：

```css
:root {
  /* 情感主色 — 凯莉色 */
  --kelly: #FF6B4A;            /* 珊瑚橙，可调 */
  --kelly-soft: #FF6B4A26;     /* 15% 透明底 */
  /* 底座中性色 */
  --bg-base: #0E1116;
  --bg-card: #161B22;
  --text-primary: #E6EDF3;
  --text-secondary: #8B949E;
  --border: #21262D;
  /* 状态语义色 */
  --ok: #3FB950; --warn: #D29922; --err: #F85149;
}
```

改造方式：68 处硬编码颜色 → 变量替换（一次性机械改动，独立小任务）。

### VA 三色规则（既定规范，组件必须遵守）

情绪维度的渐变映射：

| 维度 | 低 | 中 | 高 |
|---|---|---|---|
| 效价 valence | 红 `#F85149` | 橙 `#FF6B4A` | 绿 `#3FB950` |
| 唤醒度 arousal | 蓝 `#3B82F6` | 橙 `#FF6B4A` | 红 `#F85149` |
| 社交 social | 灰 `#8B949E` | 橙 `#FF6B4A` | 紫 `#A371F7` |

组件规格：
- **情绪滑块/展示条**：按上表渐变插值着色；数值是连续渐变不是分段跳色。
- **标签颜色**：按 `level/total` 比例取色（不是绝对值）。
- **热度标签**：阈值 `[0, 10, 20, 30]` 四档（cold/warm/hot/blazing），档位色沿用社交灰→橙→紫。
- **进度条**：一律动态计算，**允许 >100%**（溢出不截断样式）。
- **弹窗**：一律按需加载（async + loading 态），不随页面首屏拉全量。

### 情绪可视化组件（新，情感层核心件）

1. **VA 轨迹图**（ActiveConsciousness/关系面板复用）：valence × arousal 二维散点 + 近 24h 轨迹线，点色按时间渐隐。技术原型是"情绪坐标"，视觉感受是"她的心情轨迹"。
2. **心跳心情曲线**：现有心跳图叠加 valence 色带（背景条按 VA 三色规则渐变填充）——一眼看出"哪段时间她开心/低落"。
3. **关系温度计**（P0-冲突修复用）：修复进度 + 想念值双刻度，水银柱走凯莉色。

### 页面改造清单

| 页面 | 现状问题 | 改造 |
|---|---|---|
| Dashboard | 纯技术指标 | 顶部加"她现在"卡：当前情绪氛围色 + 一句话状态 + 心跳脉冲点（凯莉色呼吸灯） |
| ActiveConsciousness | 数字裸奔 | 情绪六维→VA 轨迹图 + 关系温度计；配置 tab 套 tokens |
| FreeConsciousness | 日志列表感 | 沉思流卡片化（每轮一张"思绪卡"，discovery 高亮凯莉色） |
| PassiveConsciousness | 模板编辑器 | 模板变量实时预览（左侧编辑右侧效果） |
| Analysis | 报表感 | 加学习报告面板（P0-1） |
| **关系面板（新页）** | — | 时间线 + 纪念日 + 我们的故事（P1-3 落地时建） |

### 进度条/弹窗已知规则（避免踩过的坑）

- 进度条动态计算、允许 >100%；标签色按 level/total 比例；热度阈值 [0,10,20,30]；弹窗按需加载（async+loading）；数字类标签不做花哨动画（可读性优先）。
